Put it in front. Leave the app alone.

Fit-it is a reverse proxy. Your users reach the app through it, and it reshapes the app's API responses per user.

1

Deploy the proxy

Point Fit-it at your app and send users through it. It reads the app's OpenAPI spec and injects a chat widget into the pages. No code changes, no redeploy.

2

Users ask for a change

"Hide the DNI column." "Add an age column." The agent explores the API as that user, writes a small Python hook and runs it on their real data before saving.

3

Their app changes, nobody else's

From then on the proxy runs that user's hooks on every matching response. Other users keep the app exactly as it was.

Personal software, with the guardrails operators need.

Everything a user changes is scoped to them, checked before it runs, versioned and traced.

One app, a version per user

Hooks belong to the user who asked for them. The same screen can show a discount to the manager, hide a column for reception and add a field for the doctor.

No app changes

The app is deployed as-is behind the proxy. No SDK, no plugin, no redeploy.

Safety sandbox

An AST guard, a time limit and an output cap on every hook. A failing hook returns an error, never unfiltered data.

import osopen()502 hook_failed

Feature marketplace

Publish a hook that works for you. Colleagues read the exact code, try it on their own data and subscribe to a pinned version. Accept updates when the owner ships one, or make a copy and edit it.

published @1 v1subscribed v1update available v2make a copy

Traceability

Every prompt, tool call, saved or rejected hook and hook run lands in an event journal, exported over OpenTelemetry, with a live Sankey view at /traceability.

Any model

The agent runs on Pydantic AI. Pick the provider with one variable and keep your own key.

FITIT_MODEL=openai:gpt-5-minianthropic:claude-opus-5-5ollama:qwen3

Versions and undo

Every saved version is kept. "Undo my last change" is one sentence, and every change is tried on your data before it is saved.

Parallel conversations

Open several chats and run them at once. If two touch the same hook, the second rereads it instead of overwriting.

  • AST guard before anything runsNo imports, no file or network access, no dunder tricks. Rejected code is never saved.
  • Time and output limitsEach hook run has a wall-clock limit and an output cap. The agent is rate-limited per user.
  • Fail closedIf a hook fails, the request returns 502. Users never get the unmodified data by accident.
  • The user's own session, API onlyHooks read data only through the app's API with that user's cookies. No database access. Shared features run as the subscriber.
  • Every change on the recordPrompt, generated code, validation result, diff and each run are traced per user.
