La idea

Un sastre delante de cualquier aplicación.

1

Lo pides

En un chat que aparece dentro de la propia aplicación.

2

Se cose

Un agente lo convierte en un pequeño hook de Python, revisado y probado.

3

Es tuyo

Se aplica en cada petición, pero solo para ti.

Cómo funciona

Un proxy con aguja e hilo.

El navegador solo habla con el núcleo de Fit-it. El núcleo reenvía cada petición a la aplicación con la sesión del propio usuario y, antes de devolver la respuesta, le aplica los hooks de ese usuario.

  1. El núcleo pregunta a la app quién eres y carga tus hooks.
  2. La petición llega a la aplicación tal y como la enviaste.
  3. Tus hooks transforman la respuesta y el chat se cose en la página.

Lo que el chat ya hace.

  1. Varias conversaciones

    Cada ventana es un chat. La pestaña toma el título del primer mensaje y pueden ir en paralelo.

  2. Voz, además de texto

    El micrófono dicta el cambio. Enter envía; Shift + Enter añade una línea.

  3. My features

    Cada cambio se ve, se pausa, se deshace o se publica. Cada guardado es una versión.

  4. Marketplace

    Buscar, leer el código, suscribirse tras una prueba, aceptar una actualización, copiar o reportar.

  5. El panel se queda

    Se puede cambiar de tamaño y el historial de cada conversación se guarda.

  6. Todo queda trazado

    Petición, herramientas, código y cada ejecución, por usuario, visibles en la vista de trazas.

Por dentro

Entra una frase. Salen nueve líneas.

«Aplica un 15% de descuento a las facturas emitidas en viernes.»Marta, en el chat
  • El agente lee la descripción de la API de la aplicación y consulta los datos como Marta.
  • El hook solo ve lo que Marta ya puede ver, con su sesión.
  • Cada guardado es una versión: «deshaz mi último cambio» y vuelve atrás.

def run(data, ctx):
    for inv in data["data"]:
        day = date.fromisoformat(inv["posting_date"])
        if day.weekday() == 4:  # viernes
            inv["grand_total"] *= 0.85
    ctx.log("viernes con descuento")
    return data

Cuatro reglas que no se aflojan

Cortado a medida, cosido firme.

Cero modificaciones

La aplicación funciona tal como viene. Sin parches, sin plugins, sin redespliegues.

Nunca más de lo que ya ves

Los hooks solo llegan a los datos por la API de la aplicación y con la sesión del usuario.

Falla cerrado

Si un hook se rompe o se pasa de tiempo, el usuario ve un error. Nunca datos sin filtrar.

Todo queda trazado

Petición, código, validación, diff y cada ejecución, por usuario.

Puntos clave

Seis razones que caben en una reunión.

  1. Cualquier aplicación web

    Se coloca delante, sin cambiar su código. Quitarlo es volver a la dirección de siempre.

  2. Por persona, no por empresa

    Cada usuario tiene su versión; lo que pide uno no afecta a los demás.

  3. Seguro por diseño

    Guard AST, límite de tiempo, fallo cerrado y solo la sesión del usuario.

  4. Auditable

    Cada petición, código y ejecución queda trazado por usuario.

  5. Sin atarse a un proveedor de IA

    Una variable elige el modelo. En local, los datos no salen de casa.

  6. Lo bueno se propaga

    El marketplace convierte el cambio de uno en mejora para el equipo.

El pitch

Explicación en treinta segundos.

30 segundos

Todo el mundo usa software que casi le encaja, y tiene una lista de pequeños cambios que nunca entran en un sprint. Fit-it se coloca delante de cualquier aplicación web. Cada usuario describe el cambio en un chat, un agente lo convierte en un pequeño hook y, desde ese momento, esa persona ve su versión de la aplicación. La aplicación no se modifica, sus permisos siguen mandando y cada cambio queda auditado. El mismo software, a la medida de cada persona.

Siguiente paso: un piloto. Un equipo, su aplicación de siempre y Fit-it delante. Medimos cuántas peticiones resuelven sin abrir un ticket.
